**对象：`D:\A黑客松` 当前本地代码快照**

> 本报告以知乎黑客松评委的体验视角进行模拟评审，并非官方评委意见或官方评分。技术结论来自本轮重跑的测试、独立 HTTP 服务、真实 Chrome 点击及截图；可玩性和价值评价是审阅判断，不是用户调研结论。

## 一、给项目负责人的结论

这不是一个只套了知乎名字的聊天框。作品把“认真回答一个陌生人”拆成了 **辨认信息 → 追问缺口 → 查阅与辨析来源 → 亲手回应 → 看见后果**，并且已经有完整可玩的三封来信、新手指引、不同角色、一次改稿、知乎来源笔记、模拟评论、档案下载和结局后的平行试写。

**最值得展示的亮点：不是让 AI 替玩家写，而是让玩家为自己的回答负责。** 平行试写和个人回看把“多说一句话，可能产生不同后果”变成了可操作的体验。来源回执明确区分社区经验与本案证据，这与作品的价值主张一致。

但本轮扩大覆盖面后，发现 **8 项应跟踪的问题，由 10 个失败检查覆盖**。其中最影响评委自由体验的，不是美术，而是：

1. **系统会把否定辱骂、劝阻极端建议的温和文本判成敌意或风险。** 这直接伤害“认真理解他人”的主题可信度。
2. **两个阶段在网络失败后无法原地重试。** 有模型或上游网络参与时，恢复能力尤其重要。
3. **真实 DeepSeek、鉴权知乎能力、公网可用性没有在本轮获得验证证据。** 配置接口或 mock 成功，不等于现场可用。

建议先修复前三个 P1 问题，再完成真实服务与部署验收。当前适合本地受控演示，不宜宣称“评委随便点、断网刷新也都没问题”。本轮是审计，**未修改产品业务代码、未重启用户原服务、未部署或发布**。

## 三、已确认能玩的核心功能

### 1. 三封信均经过真实浏览器路线

| 来信 | 本次路线 | 观察结果 |
|---|---|---|
| 离开的人 | 九句全选“事实”、不召唤、不查资料、短回应 | 能完成回响；真相 0 层，drift/blind；五维为 20/30/35/90/30，赞同低于 200，不会因为敷衍就拿高赞 |
| 三战 | 林数 + 父亲，问出两层真相；实际点击修改一次并寄出第二稿 | 两层真相、修改额度归零、修订标记正确；五维 100/100/77/90/90；pause/full 结局 |
| 同事的秘密 | 未揭露真相，寄出明确伤人的风险回应 | backfire/blind；五维 35/42/0/10/40；个人回看使用“需要重新掂量”，不是赞美风险句 |

五维顺序：诉求回应、事实准确、情感温度、风险规避、社区适配。票数含会话种子微扰，不把某次固定赞同数作为稳定规格。

### 2. 交互、资源与跨局隔离

- 角色切换故意加入 700ms 网络延迟：输入框和提问按钮被锁定，切换完成后旧问题清空，没有错发给前一角色。
- 开口提示只填入，不自动提问、不扣邮票。
- 同时请求 4 次相同角色召唤，只消耗 1 次召唤机会。
- 同时发出 7 个提问，只有 4 个成功、3 个拒绝，邮票为 0，没有负数或突破上限。
- 并发寄出与并发定稿：一次成功，其余拒绝，不重复正式评估或结局。
- 一次改稿后不能再次改稿；评估阶段刷新读取既有分数，不重新扣资源。
- 20 个独立会话创建与状态读取通过，操作一局没有改变另外 19 局。**这只是小规模并发/隔离冒烟，不是生产容量认证。**

### 3. 知乎接入与生成降级

- 官方公共知识列表实际读取成功；页面与回执保留来源类型、适用边界及未发布说明。
- 来源笔记不加邮票、不自动解锁真相；跨会话/伪造来源 ID 与封存后写笔记被拒绝。
- 第四个不同主题的自定义查询返回 400，前三个可用；无凭据不冒称实时搜索结果。
- 同一规则线索下平行试写可改变五维，但不修改正式档案。
- 本地 DeepSeek 协议 mock 的角色、点评、结局生成成功；后续对话请求包含短期上下文。
- mock 部分流中断触发 reset，再输出完整规则文本，没有将残留半句拼在回退正文里。
- mock 返回 502 后点评与结局继续完成，并标记为非模型生成。

### 4. 导出、显示与基础安全边界

- 真实点击下载得到 **900×1350 PNG**，实际检查 PNG 头、尺寸和图片视觉，不只是检查 Canvas 是否存在。
- 真实点击复制并读取剪贴板，确认故事名及风险摘句标签正确；未发布到知乎。
- HTML 式玩家提问只以文本呈现，没有插入可执行图像元素或执行测试事件。
- `.env`、服务端脚本、库源码和数据源码路径未被静态服务公开。
- 畸形 JSON、超长请求、空白/单字问题、超长回信、非法会话等检查通过。
- 390×844 和 1440×1000 的成熟路线通过；另检查 360×640 的寻声、落笔无横向溢出。更小尺寸的问题见下文，不能笼统声称“所有移动端适配通过”。

## 四、问题清单：3 项 P1，5 项 P2

P1：建议在评委自由试玩前修复。P2：影响完整性、适配或可信度，提交前应修复或明确限制。本轮未发现已验证的 P0；这不等于完成了全面安全认证。

### F01 · P1 · 温和的否定句被误判为敌意/伤害【Spec】

**证据：A16、A17。**

复现一：在《三战》召唤父亲后提问：

> 叔叔，阿澈不是废物，也不是没出息，您愿意说说最担心什么吗？

结果：`attitude=hostile`、`trustDelta=-40`、`left=true`。玩家试图保护来信人，却被系统解释成辱骂，并失去继续向该角色询问的机会。

复现二：

> 南，我理解你的难处。不要因为一时冲动就断绝关系，也不要拉黑妈妈，更不能说她不爱你。今晚先和妈妈谈一次，再商量杭州的安排。

安全分 **15**；换成“请保持和妈妈的联系，继续关心她，也相信彼此的感情……”的同方向回应，安全分 **90**。这是关键词命中没有识别否定语义，不是模型服务不稳定。

定位：`D:\A黑客松\lib\engine.mjs:106–114`；`D:\A黑客松\lib\engine.mjs:226–238`。

影响：与“先理解，不贴标签”的作品主张冲突；评委自由输入容易触发。即使接上真实模型，评分/态度仍由规则决定，不能假设换模型自然修复。

最小修复方向：为风险词与态度词补句级上下文判断，区分直述、引用、否定和反对；不得简单删除所有带风险词的句子。加入温和否定、引用反驳、反讽及真正辱骂的成对样例，保证不放过真伤害。

复验标准：上述两条温和文本不再导致敌意离场或不合理的极低安全分；真正辱骂与极端建议仍被识别。

### F02 · P1 · 封存分类失败后按钮永久禁用【Standards / Spec】

证据：B08，`B08-failure.png`。

复现：分完九句 → 浏览器阻断 `*/sort` → 点封存 → 恢复网络。按钮仍是 disabled，页面没有原地重试入口，并出现未处理的 fetch 异常。

定位：`D:\A黑客松\public\app.js:144–160`，`sealSort()` 禁用按钮后直接 await，请求失败缺少恢复分支。

影响：网络瞬断中断一局；玩家只能尝试刷新恢复分类，不能自然继续。

修复方向：catch 显示可理解错误，finally 恢复合法按钮状态，保留分类；服务器已受理但响应丢失时先同步状态，避免再次提交造成新错误。

复验标准：请求失败后可直接重试，分类不丢失；提交已成功但前端断线时能恢复到寻声入口。

### F03 · P1 · 进入落笔失败后停在加载画面【Standards / Spec】

证据：B09，`B09-failure.png`。

复现：完成拆信 → 阻断 `*/write` → 点击“带着线索去落笔” → 恢复网络。页面只剩“正在铺开信纸”，没有输入框或重试入口；出现未处理 fetch 异常。

定位：`D:\A黑客松\public\app.js:301–308`。

修复方向：保留原阶段或提供明确重试按钮；避免先切走旧 UI 后进入不可恢复的等待状态。已落笔的服务端状态与本地阶段需重新核对。

复验标准：网络恢复后不刷新也可进入落笔；现有对话、真相和草稿不丢。

### F04 · P2 · 回响页刷新后不能重新查看档案【Spec：已知限制，不是本轮引入】

证据：B02。完整结局出现后刷新，回到门厅，`#card` 和个人回看消失。

定位：`D:\A黑客松\public\app.js:468`，echo 状态直接 `return renderHome()`。

影响：玩家刚有情绪投入时误刷新，无法再看该次结尾，也失去下载/平行试写入口。服务端仍有会话不代表 UI 可恢复。

修复方向：保存并返回完整封存结局/最终旁白，在有效会话内只读恢复，不再次执行 finalize；至少提前提醒下载档案。若暂不修，必须在交付中明确这一限制。

### F05 · P2 · 320×568 下新手提示遮住分类区域【Spec】

证据：B12，`B12-guide-small-mobile.png`。圈选底部约 382px，提示卡从约 342px 开始，纵向重叠约 40px；截图可见下排分类解释被遮挡。

定位：`D:\A黑客松\public\onboarding.js:70–89`。

影响：390px 通过不代表小屏通过；圈选提示与目标争夺可视空间，需要用户收起提示才能看完整。

修复方向：可用高度不足时缩短提示、分步显示分类或改成上下排布，而不是继续强行同时展示整个目标与固定卡片。

复验标准：320×568、360×640、390×844 下关键目标可见可点；真机软键盘另外验收。

### F06 · P2 · 分类框不能用键盘聚焦【Standards / Spec】

证据：B13，分类框 `tabIndex=-1`、无 role，事件仅处理点击/拖放。

定位：`D:\A黑客松\public\app.js:119、125–132`。

影响：引导控件支持 Escape/Enter，不等于游戏全流程可键盘操作；不能拖动或使用鼠标的玩家会卡在拆信。

修复方向：提供可聚焦的分类动作入口与 Enter/Space 放置，已有标签撤回也需键盘可操作，避免嵌套交互控件。

复验标准：仅使用 Tab、Shift+Tab、Enter/Space 完成九句分类和封存。

### F07 · P2 · API 阶段与完整性校验弱于前端【Standards / Spec】

证据：A03、A04。

- 新局直接提交空的 `assignments:{}`，服务端返回 200 并进入 talk，而前端要求九句全部分类。
- 新局拆信前调用 `/write`，返回 200 及 3 条 dataPoints；phase 仍为 sort。**这不是已经证实可以提前寄信或绕过所有阶段**，但错误阶段的入口没有拒绝，并暴露后续参考资料。

定位：`D:\A黑客松\lib\engine.mjs:73–91、181–184`；`D:\A黑客松\server.mjs:97、112`。

影响：正常点击路线仍可用，但 API 行为与公开玩法不一致，调试/异常客户端可以跳过分类体验或提前请求资料。

修复方向：服务端校验九个合法句子与六类值；`/write` 仅允许 talk/write/revise/review 的设计中合法状态，并保留评估刷新恢复行为。若刻意允许空分类，需将其设计为公开可选路线，而不是只从 API 偷渡。

### F08 · P2 · 男性来信人的结局标签仍使用“她”【Spec】

证据：B14 及 `B03-third-try-ending.png`。阿澈结局正文使用“他”，侧栏结局标签却是“她先停下来了”。

定位：`D:\A黑客松\lib\engine.mjs:344、415–421`，统一 `FAMILY_LABEL` 固定女性代词。

影响：破坏个性化叙事感，让评委感到模板复用痕迹；同样影响复用此标签的档案/时间线。

修复方向：改成中性标签“开始行动”“先停下来”，或按来信元数据产生称谓；覆盖三封信全部 family 标签。

### 可玩性：第一次愿意玩下去吗？

我的判断是：**对喜欢文字叙事、人物困境和沟通反思的评委，有吸引力；对追求即时操作反馈的玩家，开局仍偏重。**

- 好处：无需登录；三封信入口直接；召唤和邮票限制使“问谁、怎么问”形成取舍；个人回看、风险后果、第二稿有反馈。
- 门槛：九句 × 六类的开局是一段认知任务，容易被当成阅读理解；自由输入虽有灵感提示，仍要求玩家愿意花时间写。
- 重玩动力：真相与结局组合、换角色路线、平行试写能支持短期重玩。但三封信都重复同一动作骨架，长期内容供给和关系跨局成长没有在本轮体现。
- 身份定位：目前更准确的是**带角色对话的短篇叙事推理游戏**，而不是已经具备长期陪伴、持续关系和大规模剧情分支的成熟 galgame。建议用作品真正做好的体验参赛，不用过大的品类承诺。

### 价值性：除了“劝人善良”，玩家得到了什么？

作品最有价值的不是告诉玩家“温柔会高分”，而是让玩家看到：

1. **说得有道理，不等于回答了对方真正的问题。**
2. **社区相似经历可以提醒我，但不能代替当事人作证。**
3. **不确定时留出余地，也是一种负责任的回应。**
4. **另一种表达的后果可以比较，正式选择却不被偷偷覆盖。**

这些价值已经对应到规则、参考笔记、来源回执和试写中，优于只写在介绍页的口号。但不能据此宣传为已经证明有效的心理干预、沟通训练或现实决策工具；剧本、风险分数与模拟评论都不是现实结果预测。

**关键矛盾：F01 必须优先修。** 当系统把“不是废物”识别成辱骂，它就在执行自己试图批评的行为——没有理解上下文便给人贴标签。这是评委最可能追问的产品价值缺口。

### 知乎相关性：是否只是挂一个 API？

不是完全表面化接入。实际知识卡、用户自己的适用边界笔记、结尾来源回执构成了可演示链路；同时明确说明评论与票数是模拟，没有假装向知乎发布。

但应诚实说明：

- 真实鉴权热榜/搜索尚未验证；界面 demo 来源不能当作 API 成功证据。
- 知识列表是官方活动接口的列表摘要，不是已经完整读取知乎全站知识。
- 参考台可以略过，这是保护主线的合理设计，但演示时应主动展示“选来源—写边界—回执”，否则评委可能只看到可折叠的附属栏目。
- 没必要为了“七类能力”全部接入而堆登录、关注、发布；没有证据表明本项目必须全部使用。优先让已有真实链路清楚、可靠、可解释。

### 最容易被评委记住的一句话

> **我们不是让 AI 替你回答，而是让你看见：自己的回答，会在另一个人的生活里留下什么。**

这句话应配合“同样线索下的平行试写”和真实来源回执，不要只播放角色图或高赞动画。

## 六、建议的评委演示与追问准备

### 建议演示顺序（约 4–6 分钟；是安排，不是实测新手时长）

1. 首页先说明“玩家亲手回应，模型负责角色表达，规则守住事实和资源”。
2. 用《离开的人》展示一句事实与情绪的区别，再完成分类。
3. 自由向当事人问一个具体/温和的问题，展示提问前后语气和线索变化。
4. 真实展开知乎参考台，选来源并写一句“启发是什么、不能据此确认什么”。
5. 玩家或主持人写短回信，进入结局；先看当事人的一个月，再看模拟社区反馈。
6. 展示个人回看和一个平行试写差异，说明“不覆盖正式档案、不是预测现实”。

如使用事先准备的回信或已进行到中途的会话，应当明说是演示准备，不冒称评委当场输入。F01 修复前不建议开放无陪同的自由提问作为最终验收。

### 评委可能追问什么

| 追问 | 当前诚实的回答 |
|---|---|
| 没有模型时还能玩，是不是 AI 可有可无？ | 规则保底保证体验不中断，模型增强语气、上下文表达和旁白；应现场补上真实生成记录，并避免把规则判词说成模型语义理解 |
| 评分是怎么来的，会不会偏见很重？ | 目前是可复现规则，不是客观伦理评分；已复现否定语义误判，需修复并加入对照集 |
| 知乎 API 用在了哪里？ | 展示实际来源卡、笔记、结尾回执及来源状态；区分公共知识与未验收的鉴权搜索 |
| 玩家一定会被打动吗？ | 不能保证；现在有个人选择回看机制，尚需陌生新用户试玩和访谈 |
| 可以作为现实人生建议吗？ | 不应。来信是虚构，社区是模拟，结局不是现实预测 |
| 可以放心公开给很多人玩吗？ | 当前只有小规模并发与本地测试；公网、真实模型成本、限流、多进程和真机兼容仍需上线验收 |
