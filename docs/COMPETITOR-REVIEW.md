# 五个参赛站点的真实体验记录

日期：2026-09-13。用户提供的六条链接中有一条重复，去重后为五站。本文是一次有限范围的浏览器观察，不是竞品完整审计，也不把营销文案或 HTTP 200 等同于真实官方能力证明。

## 怎么体验的

- 使用本机真实 Chrome headless，每站独立临时浏览器上下文，1440×1000 桌面视口，并对部分实际页面切换 390×844 移动设备视口。
- 使用 Chrome DevTools Protocol 的鼠标按下/抬起操作点击页面，输入用浏览器输入事件；不是只下载 HTML 或只看截图。
- 观察公开界面、状态变化、应用请求路径/状态码；不读取源码、访问账号后台、绕过登录、提交真实身份或发布内容。
- 截图及逐步记录保存在 `artifacts/competitor-review/`。应用接口可使用自己的缓存/演示数据，因此看到带 `zhihu` 的接口返回 200，并不能证明其后台实时调用了知乎官方服务。
- 临时访问者标识已在文本记录中脱敏。截图仅为本地分析证据，不进入游戏美术目录，默认排除在版本追踪与容器构建之外。

## 1. 带节奏

站点：<https://sheepsky.com/>

### 实际走到哪里

打开门厅 → 展开完整规则 → 点击预设，更换虚构公司与基因标签 → 点击开始 → 跳转到知乎登录页面，停止授权。没有进入真实交易回合，不能声称验证了 AI 居民生态或胜负结算。

### 观察与评价

- 纸质档案质感、少量蓝红强调色、公司设定表单有比较一致的题材表达。
- 用三个限制解释核心矛盾：不能无成本退出、情绪影响可用资源、行为会积累监管压力。其价值不是数值多，而是**行动与后果的因果链容易说明**。
- 初始自定义表单和术语较多，需要额外理解；点击主入口后需要知乎登录，与“离线可玩”的宣传同时存在。本次实际体验停在登录边界。
- 浏览器看到应用自身的 `/api/zhihu/corpus`、`/api/zhihu/hot` 返回成功，以及知乎登录跳转；未验证其上游数据的新鲜程度或来源。

### 借鉴但不复制

借鉴“行动后果可观察”的通用原则。《回声邮局》不是操纵舆论，而是在结局后用同样线索试写另一封回信，比较后果。没有复制交易、基因、监管、公司设定、数值或视觉布局。

证据：`initial/sheepsky-home.png`、`play-1/sheepsky-preset.json`、`play-2/sheepsky-oauth-boundary.json`。

## 2. 知乎洪荒录

站点：<https://famous-brigadeiros-22cdbd.netlify.app/>

### 实际走到哪里

开局 → 选择一种生灵设定 → 读到抉择后的叙事和数值变化 → 打开天道公报 → 检查移动设备视口。未通关全部纪元，也没有授权知乎通行证。

### 观察与评价

- 角色大图、章节进度、场景选择和结果区让人很快感到“这是游戏”，而不是工具表单。
- 选择后集中列出本次变化，比只默默修改顶栏数值容易理解。本次观察到底部战力从 1,500 变为 4,000。
- 首屏同时存在大量状态、装备、因果、内容标签，桌面上部分顶栏字段被挤成竖排；在 390px 设备模拟下页面布局宽度约 1192px，因此不能仅凭 `scrollWidth===innerWidth` 就声称适配良好。
- 知乎通行证、公报和大量知乎式文案可见。公报带有“认证文献”等叙事化字样，但本轮选择/公报操作没有提供可验证的官方实时内容证据；这不等于断言其没有任何接入。

### 借鉴但不复制

只借鉴“阶段位置清楚”和“结果变化集中解释”。本作仍保留四步回信流程，不增加修仙资源、装备、因果树或神兽变体。

证据：`play-2/honghuang-choice-1.json`、`play-2/honghuang-zhihu-bulletin.png`、`play-2/honghuang-mobile-bulletin.json`。

## 3. StoryDive / 入局

站点：<https://storydive-10wtw01.org/read/huatangchun>

### 实际走到哪里

打开阅读页 → 点击故事图谱 → 切换入局点/分支树 → 点击一条分支 → 返回阅读并出现对戏界面和开卷覆盖层。看到了对戏、分叉、改写、单独/群像、人物选择和输入框。

**没有验证成功生成一段角色回复或完成一条新支线。** 深层流程中开卷覆盖层与异步渲染影响了后续操作定位，探针在选择器步骤停止；没有把这种自动化未完成冒充接口失败。

### 观察与评价

- 场景插图、克制的阅读列宽、作者/来源归属让沉浸感成立；单独的图谱页面承载复杂信息，减少正文负担。
- 互动入口绑定到一个具体情节，而不是让新玩家面对完全空白的聊天输入框。
- 图谱可视化有助于整理角色与事件，但浮层同时打开时会抢占阅读空间。
- 页面明确标注知乎盐言故事及作者；看到的是来源归属与站内阅读/图谱请求，未独立核验原故事授权链、实时拉取或生成后端。

### 借鉴但不复制

借鉴“先给一个可理解的开口上下文”。本作只提供基于自身来信线索的问法灵感，选中仅填入，不自动发送；没有复制原文、角色、剧情、章节图、配色组合或故事图谱结构。

证据：`initial/storydive-home.png`、`play-2/storydive-branch-tree.json`、`play-4/storydive-dialog.png`；后续未完成见 `play-5/storydive-report.json`。

## 4. 观点擂台

站点：<https://arena-of-cards.app.workbuddy.host/>

### 实际走到哪里

切换到短视频话题 → 选择正方 → 开局 → 实际出牌并推进三个回合 → 展开 AI 的反驳 → 检查手机对局界面。第三轮记录为玩家 2 分、对手 1 分；不是完整八轮通关记录。

### 观察与评价

- 两个立场、一个启动按钮、一张简短规则说明，上手目标集中。
- 对手下一类牌的预告、克制说明、当轮得分让反馈易理解，用户能看见为什么输赢。
- 牌面区分绑定知乎作者/赞同/原答案链接与泛指讨论提炼，来源成为内容本身的一部分。
- 本轮反驳区域明确显示 `mock 兜底`。看到了自己的 `/api/...` 请求，不能把它当作真实模型生成成功。
- 阵营和牌面有非标准按钮式点击区域，自动化最初只找按钮没有覆盖到；改为点击实际页面元素后进入对局。手机实测对局布局宽度为 390px。

### 借鉴但不复制

借鉴简明目标、变化解释和诚实的来源标签。本作不引入卡牌、石头剪刀布克制、战斗、能量或像素风。新增文本来源标签明确显示每段是模型表达还是规则文本。

证据：`play-5/cards-play-1.json`、`play-5/cards-play-3.json`、`play-5/cards-ai-reply.json`、`play-5/cards-mobile-match.png`。

## 5. 社恐破冰船

站点：<https://zhihu-hackathon-icebreaker-production.up.railway.app/>

### 实际走到哪里

输入页面提供的公开答主示例 → 搜索 → 查看候选确认 → 点击生成 → 获得一份基于公开材料的画像及材料局限说明。后续两分身聊天需要自己的账号授权，本次未创建或授权自己的分身，也未完成破冰卡产出。

### 观察与评价

- 一个问题、三步说明、一个输入框，首屏任务非常聚焦；示例昵称降低了第一次尝试的成本。
- 搜索结果区分目标本人和提到过他的人，给用户确认环节，而非悄悄选错对象。
- 生成画像明确说明材料短、部分维度未体现，是值得学习的输出边界表达。
- 浏览器看到 `/api/candidates` 和 `/api/load` 返回内容。无法仅从结果断言底层使用哪家模型、是否实时调知乎或是否命中缓存。
- 手机搜索结果页实测布局宽度为 390px。

### 借鉴但不复制

借鉴示例输入、主动确认和信息边界。我们的检索角度按钮只填词，不自动联网；知识参考只按主题排序，不伪装成对当事人的诊断。没有复制人物画像、分身机制、产品文案或身份恢复方案。

证据：`play-1/icebreaker-public-search.json`、`play-3/icebreaker-persona.json`、`play-1/icebreaker-mobile-results.png`。

## 对《回声邮局》的结论

值得提升的不是“功能数量”，而是四个环节：

1. **更快作出第一次有意义的动作**：夜班门厅给一个明确入口，三封信按矛盾而非术语展示。
2. **让自由输入仍有扶手**：角色开口提示、检索角度提示都只帮玩家开始，不替玩家作答。
3. **结果有可比较的意义**：平行试写保持同一份线索，只换回答，比较表达与结局，不改正式档案。
4. **知乎能力不抢走判断责任**：保留归属、来源、适用边界；真实 API、缓存、演示、规则文本和模型表达分别标注。

## 原创与素材边界

没有将上述站点的源码、截图、插画、音乐、人物设定或原文复制进游戏。新界面使用本项目已有书桌、信纸及人物美术重新编排；新增视觉元素为自写 CSS 的信封、邮戳、来信架和版式。没有调用付费生图接口，也不宣称本轮生成了新插画。

这是设计相似性控制记录，不是“零版权风险”的法律保证；原有资产和刘看山形象仍应按其各自来源及活动授权范围使用。

## 观察局限及失败记录

- 五站均有访问和真实点击记录，但不是五站全流程通关。
- 早期探针出现过页面取样脚本语法、UTF-8 BOM、非标准按钮选择器和异步等待不足等错误；已区分探针失败与产品故障。脚本退出码为零只代表完成记录，不代表每个 `report.json` 都没有 `failure`。
- StoryDive 深层对戏生成未完成；带节奏在知乎登录处停止；洪荒录未跨全部纪元；观点擂台体验三轮；破冰船未授权个人账号、未完成双分身聊天。
- 站点会变化，本文仅代表 2026-09-13 这次观察。没有量化用户留存、模型准确性或可用性百分比的依据。
