# 48 小时开发排期与实现优先级

## 优先级原则

按赛事评审权重倒推：**AI 场景价值 40% > 完成度 25% ≈ 创新度 25% > 产品体验 10%**。

因此排期的第一原则是：**任何时刻手上都有一个能完整通关的版本。** 宁可只有一封信但全流程跑通，也不要三封信卡在第三阶段。

四条铁律：

1. **先闭环，再加宽。** 第一封信的四阶段打通之前，不写第二封信。
2. **降级路径与主路径同时写。** 不允许出现"等接上 API 再说"的中间状态——API 随时可能限额。
3. **引擎先于界面。** 所有玩法逻辑在纯函数里写完并测过，再做 UI。UI 出问题不会拖垮玩法。
4. **每个里程碑结束时必须可运行。** `npm test` 全绿 + 浏览器能走完当前已实现的流程。

## 砍功能的顺序（如果时间不够）

从后往前砍，**永远不砍闭环**：

| 优先级 | 内容 | 砍掉的后果 |
| --- | --- | --- |
| 必须有 | 第一封信全流程 + 降级路径 | 没有这个就没有作品 |
| 必须有 | 真相触发 + 五维评估 + 结局分发 | 失去 AI 原生性与创新度 |
| 必须有 | 知乎三接口接入 + 来源标注 | 失去 40% 的场景价值分 |
| 强烈建议 | 流式输出 | 体感从"AI 游戏"退回"表单应用" |
| 强烈建议 | 第二、三封信 | 失去重玩价值，但不影响闭环 |
| 可砍 | Canvas 档案卡 | 用 HTML 卡片 + 截图代替 |
| 可砍 | 移动端适配 | 路演用桌面端 |
| 可砍 | 会话刷新恢复 | 刷新重开一局 |
| 最先砍 | AI 生成美术资源 | 用纯 CSS 渐变与 emoji 占位 |

## 时间分配复盘

| 类别 | 占比 | 说明 |
| --- | --- | --- |
| 玩法引擎（纯逻辑） | 30% | 投入最大的一块，也是最值的——它让玩法完全可测 |
| 知乎接入 + 降级 | 13% | 降级路径的代码量与主路径相当 |
